## Feedback

`close` checks the links in the file before it moves it, but the run says
nothing about it. I had run `nokori check` just before, seen that the file was
written, and then ran `close` and re-checked the links myself, because nothing
in either output told me the move would refuse a broken link. The check had
already passed; the duplicate work was mine, but the reason I did it is that
`check` and `close` ask different questions and only one of them said so.

What would have stopped it: `close` saying, in its own output, that the link
check passed -- a line in the same shape as the existing "Closed <path>" line,
before or after it. `nokori check` cannot say it, since it deliberately leaves
`## Outcome` alone and so cannot see the file as it will be once closed. The
shared fact is the link check, so it is the one that belongs in the output of
the run that does it.

Separately, and smaller: `explain` has no `feedback` topic, and `explain flow`
carries the rules that are specific to it (which repository the item lands in,
why that is a command rather than an option on `create`, when the relation to
another item is written). Those are the reasons behind one command and they sit
scattered across `flow` and `references`. A reader who wants to know what a
`feedback` run is allowed to do has to collect them from three places. The
answer may be that a command with a rule worth arguing deserves a topic the
same way `overview` and `references` do -- this is a suggestion to weigh, not
a defect.

## Outcome

Accepted, both halves, and split into two RFCs because they are different
decisions: whether the `close` output should say the link check ran, and
whether a person outside the repository should have a topic to be pointed at.

The first is argued in `20261122-rfc-close-says-link-check.md`: one line above
`Closed <path>`, from the run that did the check. The second is argued in
`20261122-rfc-explain-how-to-feedback.md`, reshaped from the suggestion: not a
`feedback` kind explained beside `kinds`, but a `how-to-feedback` page for the
reader who sent the report, with `flow` keeping a one-line pointer and the
material about items in general staying where it is.
