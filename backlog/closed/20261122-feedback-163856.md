## Feedback

A command that shows the state of every item at once, rather than the
directory name of each, might be worth having. Not `ls` -- the image is a
status you read across the whole backlog: each item with its kind, whether it
is open or closed, what it links to, and for a `plan` how far its steps have
got. `ls backlog/open/` reads to me as a list of names, and the names carry
the date and the kind and nothing about where the work stands.

Two things make me unsure rather than sure. The first is that the answer I
want is already in the files: a link, an unchecked step, an `Outcome` section
that is still empty. A status command would be collecting what is there, not
adding a new truth, which is the kind of thing the tool already does with
`tree`. The second is the opposite worry: `explain overview` says reading over
the open items is the reader's job, and the moment there is a status line for
plan progress there will be one for a filter, and for a sort, and the tool has
turned into a manager's list.

So this is a suggestion to weigh, not a request. If it is worth doing, the
question I would want settled first is what counts as state -- a kind and a
directory are easy, a plan's progress means reading the template's boxes, and
that ties the tool to the shape of a template it has so far left free.

## Outcome

Held: worth recording, not worth building yet. The two worries in the feedback
are the reason. Collecting what is already in the files is the kind of thing
`tree` does and it fits the tool; but a status line for plan progress means
reading the boxes of a template, and the templates have so far been left free
so that a writer can shape a section to the work. Once the tool reads a shape,
that shape stops being the writer's to change.

What would settle it is the question the feedback names: what counts as state.
A kind and a directory are in the name and are free; a link and an empty
`## Outcome` are read already by `close` and `tree`; a plan's progress is the
one that would add a contract. A status command that reads only the first two
is the `ls` it is not asking for, so the reason to build it is the third, and
the third is the cost.

Nothing is done for now, and there is no follow-up item. Whoever next wants
this one should read it against the templates as they are then and decide
whether the shape is settled enough to read.
