## Feedback

When a tool rewrites a template file section by section, the `## Outcome` comment can be lost without anything noticing.

This happened while writing an RFC. The file was rewritten with a single replace of the whole body, and the replacement carried a new `## Outcome` heading but not the comment under it. The file was then filled in section by section. `nokori check` reported the item as written, and it stayed that way while the RFC was edited and committed.

The state the file was in is the one the flow says is normal for an item that is being written: `## Outcome` empty, waiting for the close. The comment is what tells that apart from a section that was emptied on purpose, and a rewriting tool does not know to keep it. Nothing in the output pointed at the section again, so the loss went unnoticed until it was remembered.

The flow already asks the writer to read the file before closing, and `close` refuses an empty `## Outcome`, so a file in this state does not close wrong -- it closes late, or is fixed by hand. What is not settled is whether a `check` that says "written" should say it about a file whose `## Outcome` has no comment, when the comment is the only mark that the section is still to come.

Reported from a repository that uses nokori, writing an RFC there.
